## Project Overview

Universal OSS Browser is an Electron-based desktop application for managing S3-compatible Object Storage Services. It uses Angular 1.x for the frontend and Node.js modules for backend operations. The project was originally designed for Alibaba Cloud OSS but has been modified to support any S3-compatible service using AWS SDK.

## Commands

### Development
```bash
npm install                  # Install dependencies
npm run build                # Build frontend code to dist/
npm run dev                  # Development mode (recommended): builds, watches, and runs
npm run prod                 # Production mode: runs from pre-built dist/
npm run dev:run:proxy        # Development mode with HTTP proxy (127.0.0.1:9090)
```

### Building & Distribution
```bash
npm run dist:win-portable    # Build Windows portable executable
npm run dist:win-nsis        # Build Windows installer
npm run dist:win-zip         # Build Windows ZIP package
npm run dist:linux           # Build Linux AppImage
npm run dist                 # Build for current platform
```

### Code Quality
```bash
npm run lint                 # Run ESLint with auto-fix on app/ directory
npm test                     # Run tests with ava
```

### Build System
```bash
gulp build                   # Full build (transpile, concat, copy)
gulp watch                   # Watch mode for development
gulp js                      # Build app JavaScript only
gulp templates               # Build Angular templates only
gulp css                     # Build app CSS only
```

## Release Process

Releases are automated via GitHub Actions when pushing version tags:

```bash
git tag v1.19.2
git push origin v1.19.2
```

This triggers `.github/workflows/release.yml` which:
- Builds for Windows (x64/ia32), Linux (x64/ia32), and macOS (x64)
- Creates portable executables and ZIP packages
- Automatically creates a GitHub Release with all artifacts

## Architecture

### Frontend (Angular 1.x)
- **Entry Point**: `app/app.js` - Defines Angular module, routing (ui-router), and i18n setup
- **Main Controllers**:
  - `app/main/auth/login.js` - Login screen and authentication
  - `app/main/files/files.js` - Main file browser interface
- **OSS Service Layer**: `app/components/services/oss2.js` - Core OSS operations using AWS SDK
  - Handles all S3 API calls (listBuckets, listObjects, upload, download, etc.)
  - Uses `aws-sdk` npm package for S3 compatibility
  - Configures endpoint, credentials, and S3-specific options (pathStyle, signatureVersion)
- **Other Services**:
  - `AuthInfo` - Manages stored credentials
  - `settingsSvs` - Application settings
  - Upload/download managers - Coordinate transfer jobs

### Backend (Node.js modules)
- **Upload/Download Jobs**: `node/ossstore/lib/`
  - `upload-job.js` - Manages resumable multipart uploads with progress tracking
  - `download-job.js` - Manages resumable downloads with chunking
  - Both extend `base.js` and emit events (statuschange, progress, complete, error)
  - Support checkpointing for resume capability
  - Use EventEmitter pattern for status updates
- **i18n**: `node/i18n/` - Translation files
- **CRC64**: `node/crc64/` - File integrity checking

### Build System (Gulp)
- **Source**: `app/` (Angular code, HTML, CSS)
- **Output**: `dist/` (transpiled, concatenated, production-ready)
- **Process** (`gulpfile.js`):
  1. Transpile ES2015 → ES5 using Babel
  2. Concatenate app JS files → `dist/app.js`
  3. Build Angular template cache → `dist/templates.js`
  4. Concatenate vendor libs → `dist/lib.js`
  5. Copy assets (fonts, icons, static files)
  6. Generate production `package.json` in dist/
  7. Run `yarn install --prod` in dist/ directory

### Main Process (Electron)
- **Entry**: `main.js` - Electron main process
  - Creates BrowserWindow loading `dist/index.html`
  - Starts static file server on ports 7123-7126 (Koa-based)
  - Handles IPC messages (openDevTools, refreshPage, installRestart)
  - Enforces single instance
  - Disables certificate validation (for self-signed certs in private clouds)

### Key Data Flow
1. User interacts with Angular UI (`app/main/files/files.js`)
2. Controller calls `ossSvs2` service methods
3. Service creates AWS S3 client with configured endpoint
4. For transfers: creates UploadJob/DownloadJob instances
5. Jobs emit progress events back to Angular via `$rootScope.$apply()`
6. UI updates with transfer progress/status

## Important Notes

- **Node Version**: Engine specifies 8.2.1 but works with Node 14+
- **Pre-commit Hook**: Husky runs ESLint on staged files in `app/`
- **Development Mode**: Recommended over production mode for stability and auto-reload
- **Build Output**: Never commit `dist/` directory (generated by build process)
- **SSL/TLS**: Certificate validation is disabled (`NODE_TLS_REJECT_UNAUTHORIZED=0`) to support private cloud deployments
- **Multi-platform**: Build scripts handle Windows, Linux, macOS differences
- **S3 Compatibility**: Uses standard S3 API via `aws-sdk`, supports path-style and virtual-hosted-style URLs
